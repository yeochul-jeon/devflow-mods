# 입력창 위 띠의 줄 배분 규칙

team-board, next-steps, prompt-coach, image-preview 가 입력창 위 띠를 함께 쓸 때 따르는 규칙입니다. 네 mod 의 코드와 테스트 기대값은 이 표에서 나옵니다. (T65, 2026-11-13 초안. 임계값은 실화면 시험 뒤 확정합니다.)

## 왜 필요한가

- Claude Code 2.1.322 까지는 바깥 mod 가 `maxRows` 를 줄이고 `teamRows`·`nextStepsRows`·`coachRows`·`imagePreviewRows` 를 붙여 `next()` 로 넘겼습니다.
- 2.1.323 부터는 mod 마다 따로 불리고 모두 띠 전체의 `maxRows` 를 받습니다. 붙여 넘긴 값은 다른 mod 에 닿지 않습니다. 줄은 설정 순서대로 위에서 아래로 쌓입니다.
- 그래서 각 mod 는 **공유 상태(`$.state`)와 `maxRows` 만으로** 제 줄 수를 정합니다. 네 mod 가 같은 입력에서 같은 표를 따르면 합이 `maxRows` 를 넘지 않습니다.
- 이 방식은 두 구조에서 같은 코드로 동작합니다. `next()` 에는 받은 `e` 를 그대로 넘깁니다(줄 수를 빼지 않고, 값을 붙이지 않습니다).

## 입력

| 기호 | 뜻 | 읽는 곳 |
|---|---|---|
| B | 띠가 쓸 수 있는 줄 수 | `e.props.maxRows` |
| T | 팀 창을 그릴 수 있음 | `team-board/me` 가 있고 `team-board/bandOff` 가 아님 |
| S, n | 다음 요청 제안이 있음, 제안 수 | `next-steps/steps.items.length` (n > 0) |
| I | 초안에 이미지가 있음 | `image-preview/draft.length > 0`, 전체 화면일 때만 |
| C대기 | 다듬기 줄을 그릴 수 있음 | `prompt-coach/band.hasDraft` 이고 `prompt-coach/flow.stage` 가 `idle` |
| C진행 | 다듬는 중(질문 만들기·질문·다시 쓰기·넣음) | `prompt-coach/flow.stage` 가 `idle` 이 아님 |

공통 조건: `hasSurvey` 면 아무도 그리지 않습니다. `isWorking` 이면 next-steps 와 다듬기 줄(C대기)은 없는 것으로 봅니다.

## 1. 누가 남는가 (B 가 아주 작을 때)

아래 순서대로 1줄씩 받습니다. 제 순위까지의 참여자 수가 B 보다 많으면 그 mod 는 그리지 않습니다.

1. prompt-coach 진행 중 화면 (C진행)
2. next-steps 한 줄 모양 (S)
3. image-preview 칩 줄 (I)
4. prompt-coach 다듬기 줄 (C대기)
5. team-board 한 줄 모양 (T)

예: S, I, C대기, T 가 모두 있고 B = 2 이면 next-steps 한 줄과 칩 줄만 그립니다.

## 2. 남는 줄을 누가 먼저 쓰는가

1단계에서 남은 참여자가 1줄씩 받은 뒤, 남는 줄은 아래 순서로 씁니다. 앞 항목이 쓴 뒤의 나머지를 뒤 항목이 씁니다.

| 순서 | 쓰는 것 | 줄 수 | 조건 |
|---|---|---|---|
| 1 | prompt-coach 진행 중 화면 | 모양에 따라(질문 모양은 `questionShape`) | B 에서 칩 줄(I, B ≥ 2 일 때)과 팀 한 줄(T, B ≥ 3 일 때)을 뺀 줄 안에서 |
| 2 | next-steps 펼친 목록 | n + 2 (가로줄 + 제안 n + 닫기 줄) | B ≥ (n + 2) + 칩 줄 + 다듬기 줄 + 팀 한 줄. 아니면 가로줄 있는 한 줄(2줄, B ≥ 2 + 칩 줄 + 다듬기 줄 + 팀 한 줄) 또는 한 줄(1줄) |
| 3 | prompt-coach 다듬기 줄 위 가로줄 | 1 | 다른 참여자(S, I, T)가 있고, B ≥ next-steps 줄 + 칩 줄 + 다듬기 줄 + 1 + 팀 한 줄 |
| 4 | image-preview 칩 줄 위 구분 줄 | 1 | 다른 참여자가 있고, B ≥ 위 3번까지의 합 + 1 + 팀 한 줄 |
| 5 | team-board 팀 창 | 남은 줄 전부 | 남은 줄 = B − (next-steps 줄 + 칩 줄 + 다듬기 줄 + 구분 줄 + `image-preview/cardRows`). 카드 줄은 팀 1줄을 남기는 만큼만 뺌. 1줄 미만이면 그리지 않고, 모양(큰 창·한 줄)은 team-board 의 기존 기준으로 고름. prompt-coach 가 다듬는 중이면 한 줄 모양 1줄(B < 3 이면 그리지 않음). `team-board/me` 가 없으면 그리지 않음 |

- "칩 줄"·"다듬기 줄"·"팀 한 줄"은 해당 참여자가 있을 때 1, 아니면 0 입니다. 2~4번이 모두 팀 한 줄을 남기므로 1절에서 남은 참여자는 2절에서도 1줄을 지킵니다.
- T 는 실제보다 넓게 잡힙니다: team-board 는 보일 목록이 비었거나 혼자이고 혼자 표시를 껐을 때 그리지 않습니다. 그때 다른 mod 가 1줄을 비워 둡니다(알려진 한계).
- 가로줄(3번)은 next-steps 가 목록을 펼칠지 정한 뒤의 나머지로만 둡니다. 가로줄 때문에 목록이 접히는 일은 없고, 목록이 한 줄로 접힌 높이에서도 줄이 남으면 가로줄을 둡니다.
- C진행일 때 next-steps 는 제안을 그리지 않으므로(4절) 1번과 2번은 겹치지 않습니다. 다른 mod 도 C진행이면 S 를 없는 것으로 셉니다.
- 이미지 카드(마우스를 올렸을 때 띠가 붙드는 것)는 B 에서 위 표의 다른 줄과 팀 한 줄(T 가 있을 때)을 뺀 나머지에 들어갈 때만 띠 안에 그립니다. image-preview 는 카드를 열고 닫을 때와 열려 있는 동안 0.5초마다 그 줄 수를 `image-preview/cardRows` 에 적습니다(카드가 없으면 0). 띠는 적힌 줄 수 안에서만 카드를 그립니다. prompt-coach 가 다듬는 중에는 띠 안 카드와 칩 줄 위 구분 줄을 그리지 않습니다.

## 3. 구분

- 각 mod 는 구분 줄을 **제 줄 맨 위**에 그립니다. 쌓이는 순서를 몰라도 위 띠와 나뉩니다. 맨 위에 놓인 mod 의 구분 줄은 대화 기록과 띠를 나눕니다.
- next-steps: `── next-steps ───` (기존). prompt-coach: `━━ prompt-coach ━━━` (다듬기 줄은 2-3번 조건, 진행 중 화면은 기존 조건). image-preview: 2-4번 조건의 `── image-preview ───`. team-board: 창 테두리가 구분입니다.
- 줄이 없어도 구분되도록 prompt-coach 다듬기 줄은 맨 앞 `▎` 와 배경색 칩을 항상 그립니다.

## 4. 숫자 키

- 2.1.323 에서는 서로 다른 mod 가 같은 숫자 키를 그리면 둘 다 눌리지 않습니다.
- next-steps 는 `prompt-coach/flow.stage` 가 `idle` 이 아니면(질문 만들기·질문·다시 쓰기·넣음) 제안을 그리지 않습니다. 그 동안은 prompt-coach 화면이 줄과 숫자 키를 씁니다. (사용자 결정 2026-11-13)
- 엔진 자체 안내(Heads up)의 숫자 버튼과 겹치는 경우는 상태를 읽을 수 없어 피하지 못합니다(미검증).

## 5. 엔진 버전에 따른 차이

- 2.1.323 이상: 위에서 아래로 설정 순서대로 쌓입니다. `e.plugin` 에 제 이름이 들어옵니다.
- 2.1.322 이하: mod 들이 한 줄로 이어져 있고 `e.plugin` 이 없습니다. 줄 수 계산은 같고, 화면 순서만 각 mod 가 `next()` 결과를 두는 자리에 따릅니다.
- 계산이 어긋나는 곳이 실화면 시험에서 나오면 그 부분만 `e.plugin` 으로 갈라 처리하고 이 문서에 적습니다.

## 확인 방법

- mod 별 테스트: 다른 mod 를 `plugins: [{ name, register }]` 로 올려 상태를 세팅하고, 시험할 mod 가 그린 결과를 `maxRows` 와 상태 조합별로 검사합니다.
- 실화면: 설정 순서 3종 × 창 20·22·24·26·30·36·40줄 × 상태 6종에서 `↓ n more` 가 없고 이 표대로 줄어드는지 봅니다.
